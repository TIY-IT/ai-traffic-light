AI Status Light — Windows x64 内测版

支持客户端(7 个灯位):Codex、WorkBuddy、ZCode、Marvis、扣子、TRAE、豆包。
灯位只显示正在运行的客户端;没装的客户端不影响其他灯。

重要限制(发送朋友前请告知)
- 内测版,不是正式版;未做代码签名,首次运行安全提示请选"仍要运行"。
- Codex / ZCode 按父任务聚合已识别的子代理状态;无法确认的状态保持"不亮",不猜测结束。
- 扣子仅识别当前打开的会话;后台会话不保证。
- Claude / CodeBuddy 暂未接入。
- 包内 source/ 为完整源代码,THIRD-PARTY.txt 为第三方依赖许可材料;可现场排查修复。

安装
解压到普通文件夹,双击 Install.cmd。无需管理员权限。
安装位置:%LOCALAPPDATA%\AIStatusLightBeta
桌面入口:AI Status Light Beta、扣子/豆包/TRAE（AI 状态灯）
(检测到对应客户端才会创建对应快捷方式;没检测到的会跳过)

首次接入
1. 先安装并打开要使用的 AI 软件,再运行 Install.cmd;后装的客户端,重跑一次 Install.cmd。
2. Codex:安装会添加用户级 Hooks。按 Codex 提示审查并信任;CLI 可输入 /hooks。
   完成信任前不会收到事件。不要把"暂无状态"当成结束。
3. WorkBuddy:安装会合并设置并保留其他 Hooks。等当前任务结束后重启一次 WorkBuddy。
4. 扣子/豆包/TRAE:日常从桌面"××（AI 状态灯）"快捷方式启动。
   安装时检测不到客户端会提示输入其 exe 完整路径(只需一次,会被记住);
   也可以先打开客户端,再运行 Install.cmd。

灯的含义
绿:至少一条识别到的会话在执行;红:结束、异常或等待处理,不表示结果正确。
不亮:未收到状态、未接入、无活动或记录过期。悬停看会话详情。
对应应用主进程退出后隐藏;缩到托盘不算退出。全部退出后只留本工具托盘。
启动应用不等于运行任务,不会凭程序打开就亮绿。

扣子/豆包/TRAE 说明(实验性)
- 专用快捷方式会用仅本机回环的调试端口启动客户端
  (扣子 19222、豆包 19224、TRAE 19226),不开放局域网,不需要 API Key。
  公司设备请先经 IT 同意。本机其他程序仍可能通过该端口访问页面数据。
- 普通方式启动的实例不开启该接口,灯显示暂无状态;
  完全退出客户端,再用原快捷方式启动即恢复普通模式。
- 只读取会话 ID、标题、状态计数,不发送消息、不读取聊天正文和登录凭据。
- 不会未经确认结束正在生成的任务(弹窗询问后才重启)。
- TRAE:任务结束的红灯不依赖调试端口;生成中的绿灯需要快捷方式启动。
- 豆包信号诊断:生成一条回复的过程中运行 Check-Doubao-Signal.ps1,把输出发回给支持人员。

报错之后:把提示词发给 AI 助手
本包自带完整源代码(source/)与诊断手册(skill/status-light-doctor/SKILL.md)。
出问题时,把下面整段提示词复制给你电脑上的 AI 助手(ZCode/WorkBuddy/Codex 均可),
助手会按手册排查,不需要你懂技术。方括号处换成你的实际情况。

卸载
Uninstall.cmd:只清理本工具的程序、快捷方式与其写入的 Hooks(自动备份,不碰其他配置)。
